# Session 2026-09-10-05 — FLASH 4

## What this is
A correction to flash 3, which broke two-finger right-click entirely.

## The mistake, stated plainly
Flash 3's driver change rested on a premise I asserted confidently and did not
check: **"two fingers landing is unambiguously a scroll, never a tap."**
Two-finger tap for right-click is exactly a two-finger tap.

The bypass sent any two contacts straight to `MoveScroll`, which on lift goes to
`None` and never reaches `Tapped`. So `tap_count` never incremented and
`button2` never fired. Right-click stopped working completely — not an edge
case, a whole gesture gone.

It also ate single-finger taps. MEASURED: two ~40ms contacts with ZERO pointer
movement emitted scroll ticks, which a single-finger still tap cannot
legitimately do. Those were momentary second contacts — a finger roll or a
knuckle grazing — instantly bypassing the tap path.

I also proposed a debounce as the fix before Ryan reported right-click. That
would ALSO have been wrong: a two-finger tap lasts 40-80ms, well past any ~17ms
guard, so it would still have been routed to scroll.

## The actual fix
The distance test was never the problem. It is the ONLY thing that can separate
two-finger scroll from two-finger tap, because the contact count cannot. The
problem was the THRESHOLD being shared.

`DIGITIZER_MOUSE_TAP_DISTANCE` must be large enough to tolerate single-finger
tap drift — measured at 28-66 accumulated units here, hence ~50 — and that same
largeness is what made two-finger scroll wait.

So multi-finger contacts get their own threshold:
`DIGITIZER_MOUSE_MULTI_SCROLL_DISTANCE`, default 20, `#ifndef`-overridable so
future tuning needs no driver change. A two-finger tap barely moves its centroid
and still falls through to `Tapped`; a two-finger scroll trips 20 almost at
once instead of travelling a tap's worth of distance.

That is the real decoupling — separate thresholds for gestures with different
tolerances, not deleting the check that told them apart.

## Post-flash checklist — all four must pass together
| # | check | result |
|---|---|---|
| 1 | typing, both halves | |
| 2 | **two-finger tap = right click** — the gesture flash 3 destroyed | |
| 3 | single-finger tap clicks reliably | |
| 4 | move → lift → two-finger scroll, prompt every time | |
| 5 | adding/removing a finger does not lurch | |

2, 3 and 4 are the three that have been trading against each other for four
flashes. All three passing is the bar; any one failing means the thresholds are
still wrong, and `MULTI_SCROLL_DISTANCE` is now tunable from config.h without
touching the driver again.

## Ruled out
- `TAP_DISTANCE` as a scroll-onset lever — load-bearing for tap classification.
- Bypassing the distance test for `contacts >= 2` — destroys two-finger tap.
- A debounce on that bypass — a two-finger tap outlasts any useful guard.
